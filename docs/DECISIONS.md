# Decisions log

Format: **What was asked → What we did → Why.**

| # | Asked | Did | Why |
|---|---|---|---|
| D1 | Name "FloodSetu" | Kept **FloodSetu** | Short, bilingual, and the Setu lineage is intentional. Other projects may use the same name, so this is fine for a hackathon prototype but needs a trademark check before any real deployment |
| D2 | Contract Net Protocol, CBBA if time | **CNP with priority-ordered sequential auctions + bundles (≤2) + leveled commitment** | A one-task-at-a-time CBBA special case that is easy to explain to an operator. Full CBBA consensus rounds are logged as future work (RESEARCH §4.1) |
| D3 | `packages/baseline` separate | Baselines live in `packages/engine/src/strategies/` | Execution, monitoring, invariants and metrics must be *identical* across strategies for a fair comparison. One package keeps a single source of truth. A strategy is a pluggable `Strategy` interface |
| D4 | OR-Tools sidecar optional | **Pure-TS Hungarian** for central | Deterministic, offline, and no Python process during the demo. OR-Tools VRP is listed in LIMITATIONS |
| D5 | MapLibre GL + deck.gl | **Custom Canvas2D map renderer** over synthetic town geometry | A fully offline demo needs no tiles. We get full control of the uncertainty visual language (dashed unknown edges, cross-hatched closures, hatch fills for unverified areas, glow, flow animation), and the landing page's R3F keeps the only WebGL context. About 300 nodes, 600 edges and 23 agents render at 60fps on Canvas2D. Swapping to MapLibre for a real basemap is a renderer change only |
| D6 | Synthetic town or real overlay | **Fictional riverine town "Jalnagar"** in local km coordinates (displayed as synthetic lat/lng anchored at 25.40°N 85.00°E, labelled fictional) | No risk of being mistaken for operational data about a real place |
| D7 | Postgres/PostGIS or SQLite | **File-backed JSON stores behind repository functions** (`.data/dispatch.json`, `.data/relief.json`) | Zero setup (setup in ≤3 commands). The two separate files make the module isolation physical. A repository interface makes Postgres a drop-in |
| D8 | Socket.IO / Supabase Realtime | **2 s polling** for the live bridge | Works through any network, needs no extra server process, and is easy to reason about offline. Latency is fine for a demo |
| D9 | next-intl | Tiny typed dictionary + `useT()` hook, `en`/`hi` | No routing rewrite. Panels toggle language instantly, and the choice persists in localStorage |
| D10 | next-pwa / Serwist | Hand-written `public/sw.js` + IndexedDB outbox (`idb-keyval`) | Transparent and small, with no build-plugin coupling to Next 15. Background Sync is used when present |
| D11 | shadcn/ui primitives | Own primitives restyled to tokens; `cmdk` for ⌘K | Avoids an interactive CLI and network scaffolding. Each component is small and token-driven |
| D12 | Recharts/visx | **Own SVG charts** (sparklines, grouped bars, Sankey via `d3-sankey` layout only) | Visual consistency with tokens and a tiny bundle |
| D13 | Turborepo | **pnpm workspaces only** (`pnpm -r`) | Five packages with TS-source consumption and no build step, so Turbo's cache adds nothing here |
| D14 | Passability rules | Ground ≤ 0.5 m depth; boats ≥ 0.4 m on roads; river = boat-only; bridge = ground-only | The 0.4–0.5 m overlap reflects shallow-draft IRBs. Thresholds live in `config.ts` |
| D15 | Contradiction handling | Contested edges: **closed for ground agents, ×3 cost for boats**, and a VERIFY task is auctioned | "Prefer safe routing" (PS) |
| D16 | Verification gating | Unverified non-critical requests are **never blocked**. They carry a confidence factor (0.6–1.0) in priority. Critical requests ignore verification entirely | Invariant 7, plus ordering under scarcity |
| D17 | Extra reason code | Added `CENTRAL_REPLAN` (baseline reassignment) and `TASK_RESOLVED` (merged/withdrawn) | The PS reason codes don't cover baseline churn. Every decommit must carry a reason (invariant 9) |
| D18 | Jain's index input | Jain over **per-neighbourhood mean waits** (equality of treatment), paired with **worst-neighbourhood P90** | Jain measures equality, not level. P90 adds the Rawlsian worst-off view (RESEARCH §4.3) |
| D19 | Live real-phone SOS | The control-room browser is the dispatch brain. Phones talk to the server, which bridges to the worker | Keeps the judged engine in one place. The rescuer phone is "logged in as" a fleet unit |
| D20 | Expectant (black) triage | Not modelled | A dispatch tool must not encode abandonment decisions |
| D21 | CNP award rule | Award the **highest-utility (task, bid) pair first**: `utility = priority / (1 + bid/20)`. CBBA-style greedy consensus instead of strict priority order | Strict priority order sent boats on long trips and cut throughput by about 10 points versus greedy (measured). Combining urgency with time-to-service is what §6.3 asks for |
| D22 | Leveled commitment | **Every not-yet-started commitment** (queued *or* en route) is re-offered each tick. The holder bids with an 8-min decommitment-penalty advantage, and a switch is logged as `BETTER_OFFER`, or as `HIGHER_URGENCY_PREEMPTION` when the holder is diverted to a strictly more urgent task | Without it CNP locked in early choices, and central (which re-plans all unstarted work every tick) dominated. This is Sandholm & Lesser's mechanism (RESEARCH §4.1) |
| D23 | Boats deliver to shelters | Boats hand over at a **landing node** (boat-reachable, ground-connected). Cost = boat minutes + 0.5 × shuttle minutes. Reservation is still with the shelter | Shelters sit on dry high ground that boats can't reach. Matches the PS's "escort from boat drop points" |
| D24 | Task mode by depth | Mode is chosen by **reachability on the COP**: boats from ghats, ground from shelters. Depth is only the tie-break. Re-derived each tick while a task is untouched | Depth-only selection caused ground tasks to bounce as the water rose |
| D25 | Size-up rule | A large **unverified** claim (>12 people) gets a first wave of ≤12 people of lift. The full demand opens once the first unit verifies on site. **Never zero**, so invariant 7 holds | Copy-paste "50 people trapped" spam otherwise pulls most of the fleet (measured in fraud-mix: CNP mean TTS 41.9 → 32.3 min) |
| D26 | Extra metric | Added **urgency-weighted TTS** (critical minutes ×10, urgent ×4) next to plain mean TTS | Mean TTS rewards urgency-blind nearest-first (greedy). The triage objective needs its own number. Both are always shown |
| D27 | Bundles ≤2 (CBBA-style) | **MAX_QUEUE = 1** for all strategies | After D22 (per-tick re-auction of unstarted work), pre-bundling a second job hurt. Across 6 scenarios × 2 seeds, CNP went from 65.9% → 68.5% rescued, critical TTS 30.1 → 24.9 min, weighted TTS 38.6 → 34.5 min. Late binding beats early commitment |
| D28 | — | **Rejected:** an extra queued slot reserved for critical work | It made the cascade panel show a same-tick owner, but critical TTS got *worse* (25.8 → 28.9 min) because critical jobs queued behind far, busy boats. Outcomes beat optics |
| D29 | Framer Motion | Not used. Micro-interactions are CSS transitions; scroll choreography is GSAP + Lenis | One fewer runtime dependency, and GSAP already drives the landing |
| D30 | "Realistic water (refraction…)" | Custom GLSL: animated multi-sine normals, fresnel sky reflection, moon specular, ripple-distorted **fake refraction** tint (no render target) | Real refraction needs an extra scene pass. The fake keeps the landing at 60fps on integrated GPUs |
| D31 | Service worker everywhere | SW registers **only in production builds** (or `?sw=1`) and uses stale-while-revalidate | Dev chunks aren't content-hashed: a cache-first SW served a stale, truncated chunk (found and fixed during testing) |
| D32 | Stranded victims | When a boat fails with people aboard, they become a new **critical** incident at the boat's location, tracked inside the same cascade | Otherwise the cascade would silently "lose" the people who were on board |
| D33 | Rename (judges) | **JalSetu → FloodSetu** everywhere: UI, `@floodsetu/*` scope, request IDs `FS-XXXX` | Judges' request |
| D34 | "Satellite latency in real-time usage", Indian preferred | Constellation of EOS-04, NISAR-S, INSAT-3DS/3DR and Resourcesat-2A. Each product has acquisition and availability ticks, data age is shown live, and fusion is LWW by **observation time** | A real-time system has to know how old each picture is. SAR is the only flood sensor that works through monsoon cloud |
| D35 | Gauges everywhere | River gauges only on the river-front neighbourhoods (GHT, PRB, MCH) | Realistic, and it gives satellites a job. It changed bench numbers, which were re-run |
| D36 | Dam data | Fictional dams with NRLD-style fields, an explainable age/condition/hazard risk score, and downstream risk zones that add a priority term. DAM_RELEASE and DAM_BREACH events plus a reservoir model | Judges asked to mark old-dam areas as high risk |
| D37 | Phone drowns mid-request | Heartbeat watchdog (90 s), DEVICE_LOST event, invariant 10 (critical and escalated in the same tick), one-tap `in_water` SOS, alternate contact, battery early warning | Judges' scenario. A rescue must never depend on the victim's phone staying alive |
| D38 | Landing "looks cheap" | Rebuilt on the INVERSA reference: a single-shader satellite-style aerial (fields, rooftop blocks, contours, silty floodwater with along-channel current), lime used only for annotations, solid editorial blocks with hairlines and mono metadata, 3.6 px radii, no glass cards | The old water plane clipped through the terrain as metallic ribbons, and every section was the same glass box |
| D39 | Multi-language ("India has many languages") | 13 languages: **English stays the default**, Hindi is always one tap, and the regional language for the user's state is *suggested* (banner plus a third chip), never auto-switched. The signal is GPS → state (offline nearest-centroid table, no geocoding API), falling back to browser locale. The other 11 regional languages (bn, mr, te, ta, gu, kn, ml, pa, or, as, ur) cover the life-critical SOS path and status; the rest falls back to English. Urdu sets RTL. An unknown `lang` code is coerced to `en`, so it never rejects an SOS | Auto-switching on location is wrong for migrants and for border districts. A wrong guess must cost one tap, never a blocked SOS |
| D40 | iPhone app | Native SwiftUI (iOS 17, no packages) in `apps/ios`, using the **existing** web API with cookies and the CSRF header. Two modes chosen on first launch. Victim: SOS, one-tap in-water, a 3-question form, a persistent offline outbox, and status polling as the heartbeat. Rescuer: demo unit sign-in, one task card, big field actions, idempotent retries | One backend means one source of truth: the Control Room can't tell an iPhone SOS from a web one. Native gives large tap targets, haptics and a real location prompt |
| D41 | Live-data test of the iPhone app found two bridge bugs | (1) The Control Room signed in once, so when the short-lived access cookie expired every bridge push got 401 and the phones' view silently froze. It now rotates the session on 401 (refresh token, with demo sign-in as the dev fallback). (2) SOS already handed to a Control Room run were orphaned at "received" when that run restarted. The bridge now spots the sim clock going backwards and re-delivers every unresolved SOS. The iOS app also shows a "LIVE · updated Ns ago" chip | Found by comparing the phone against the server every ~10 s. A frozen feed that still looks normal is worse than an error, so freshness is now visible on the phone |
| D42 | Landing background and brand mark | Replaced the WebGL/R3F scene and the SVG backdrop with a supplied aerial river flyover, scrubbed by scroll (top = first frame, bottom = last, eased). It is encoded **all-intra** H.264 (every frame a keyframe) so reverse scrubbing is as smooth as forward, with a VP9 WebM fallback for browsers without H.264, a small file for small screens, and the poster frame only for reduced motion. Removed three.js, R3F and drei (about 1 MB of JS). New slogan: "A signal in the flood. A lifeline in motion." New minimal mark: an SOS beacon riding a wave crest with two signal arcs, in brand colours, used for the favicon, PWA/maskable icons, apple-touch icon, iOS app icon and the in-app header. The source lives in `design/icon` | Users asked for the video. A normal-encoded video stutters when scrubbed backwards because every seek has to decode from the previous keyframe. The mark keeps three ideas only: a signal, a person, the water |
| D43 | River monitoring, live alerts, live GPS, cooldown, corroboration, engineers, family SMS | **River:** three CWC-style gauges record stage every 10 min, with flow from a power-law **rating curve**, a 60-min least-squares trend and warning/danger/HFL status. It is observation only and never read by dispatch. **Alerts:** generated server-side from the bridge on threshold *changes* (river and dam), CAP-shaped, reset when the sim restarts. Shown as a banner on web and iPhone, with local notifications on iPhone. **GPS:** the owner's phone posts fixes (≥ 20 s or ≥ 30 m), and the latest becomes the team's precise location. **Cooldown:** 60 s, *confirm not block*; the server folds a repeat into the open request and upgrades urgency or needs. **Corroboration:** ≥ 3 distinct low-risk phones in one incident → verified. **Engineers:** G-16/G-17 with `engineering`, required for ground rescue of `trapped` and preferred for bridge checks. **Family:** mock SMS on sent/assigned/safe/silent, each sent once, plus a status-only `/track/<id>` page. The raw number is purged with precise location | Requested features, each built so a safety mechanism can never stop a real SOS. The re-run benchmark changed every column (D27-style honesty: new numbers published) |
